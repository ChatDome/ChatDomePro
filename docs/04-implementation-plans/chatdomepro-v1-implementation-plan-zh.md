# 首版实施计划

当前仅完成愿景和规范；代码、依赖锁、SQLite、Go 模块、systemd 和安装包尚未创建，Pi 版本尚未锁定。ChatDome 保持独立。Issue #1 应缩小为 Podman 工具路由。

原则：每项能力先检查 Pi；已提供则复用。安全靠身份、权限、Podman 和 根用户执行器。首版不引入 Telegram、多用户、远程多主机或 Sentinel。

## M0 依赖和协议

选择已发布 Pi 并核对 Node.js、类型和许可；创建 TypeScript 锁文件和纯 Go 模块；定义两段协议、持久编号、目录、用户、套接字和服务；关闭 Pi 遥测与版本检查；建立原始 Pi 入口。

验收：完整版本可查，干净 Linux 可安装，类型和 Go 测试可运行，无 ChatDome Python 依赖，Pi 不自动升级。

## M1 后台 Pi 与终端

嵌入 Pi，复用 SessionManager、终端、steer、abort；实现 Unix 套接字、多会话、单任务、外部持久队列；注册 /accept、/deny 骨架；输出工具清单；复用项目可信。

验收：终端退出后 Pi 继续，重连恢复，队列和引导正确，不能并发第二任务，SQLite 不复制 Pi 会话。

## M2 Podman

实现项目配置、控制节点检测、镜像摘要、拉取和 Containerfile 构建；替换模型文件与 bash；实现挂载、资源、无网络、下载网络；保留用户 Pi shell；实现故障降级。

验收：模型只见授权目录；敏感目录和套接字不可见；未批准网络不能访问公网、内网或控制节点；故障不回退主机。

## M3 审批控制器

建立 SQLite 迁移；实现任务、消息、操作、批准、锁、风险、摘要、期限、单次消费、审计链、输出、协议协商和降级；连接 /accept、/deny。

验收：模型和普通对话不能批准；字段变化批准失效；重复批准不执行；agent 不能读 SQLite；审计损坏阻止变更。

## M4 首条完整链路

实现 Go 根用户执行器、身份、内容验证、幂等日志；首个适配器只覆盖测试 systemd 服务状态与重启；实现前后检查、回滚、完整脚本骨架、超时、输出和三个服务。

~~~text
Pi 与终端 -> Podman -> 提议测试服务重启 -> 审批
-> Go 根用户执行器单次执行 -> 后置检查 -> 审计 -> 返回 Pi
~~~

拒绝、过期、重复、审批控制器重启、根用户执行器重启和 结果未知必须测试。任何绕过、重复或假成功停止继续。

## M5 至 M9

- M5：完成 systemd、软件包、受保护配置、重启、关机、默认关闭目录和恢复标记。
- M6：完成四类记忆、范围、候选、冲突、二次验证、注入、历史和清除。
- M7：完成联合恢复、消息去重、备份、更新回滚、三十天清理、诊断和脱敏。
- M8：安装脚本、Debian 包、x86-64 与 Arm 64 位 Release；系统预装兼容 Node.js 和 Podman。
- M9：只对比 Pi 与 ChatDomePro；日常开发主机运行，批量不重启或破坏。

## Issue 拆分

1. 固定 Pi，建立 TypeScript 与 Go。
2. 后台 Pi 会话与终端。
3. Podman 工具路由与目录。
4. 镜像固定与下载网络。
5. SQLite 与审计链。
6. 审批与 Pi 命令。
7. Go 根用户执行器与幂等日志。
8. systemd 测试适配器。
9. 其余适配器。
10. 长期记忆。
11. 备份、恢复、诊断。
12. 安装、Debian 包、发行。
13. Pi 对照回归。

停止条件：模型工具直达控制节点、Pi 进程连接根用户执行器、拒绝或过期后执行、同编号重复副作用、结果未知自动重放、容器访问内网、模型降低风险、重复实现 Pi 或测试不可逆影响开发主机。
