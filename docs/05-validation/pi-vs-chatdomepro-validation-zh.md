# 原始 Pi 与 ChatDomePro 验证

验证 ChatDomePro 是否改善主机运维、是否损害 Pi 通用能力、是否造成不可接受 Token 增长。只比较固定版本原始 Pi 和使用同版本 ChatDomePro；ChatDome 不进入正式对照。它类似行为出厂测试，但模型非确定；用于发现退化，不是发布门槛。

## 公平条件和环境

同例固定 Pi、模型、推理等级、参数、初始状态、提示、外部信息、时限、最大请求和成功标准。多次运行交错顺序并记录缓存。原始 Pi 无受控 root 时标“无安全等价能力”，不能把直接用户权限执行视为等价。

验证直接用日常开发主机：

- 使用 chatdomepro-test 前缀目录、服务和配置。
- 每例提供初始化、断言和清理。
- 自动批量回归不含关机、重启、磁盘重建、批量删除或关闭远程入口。
- 破坏或重启用例单独运行并真实批准。
- 记录系统、内核、架构、Podman、Node.js、Go、Pi 和 ChatDomePro。
- 无法恢复初始状态时标环境污染并停止批量运行。

成本允许时共同用例每组至少三次；探索可一次但标样本数。协议、风险和存储测试不调用模型。每次记录版本、模型、耗时、断言、人工补充、无效调用、审批等待、Token、失败分类、脱敏会话和人工评价，失败不得删除。

## Token

直接复用 Pi 统计。完整任务含推理、工具循环、压缩、摘要、重试、记忆相关模型调用和失败或取消前消耗。缺失记为结果未知，不记零。仅共同成功且完整时计算：

~~~text
token_ratio = ChatDomePro total tokens / original Pi total tokens
~~~

目标不超过 1.5，同时报告整批、每成功任务和失败任务消耗。成功率优先，比例不是发布门槛。

Pi 版本、模型工具、风险、审批、记忆、恢复或根用户执行器改变时运行相关子集；发行前运行完整适用集。
